WHAT WAS *NOT* CHANGED (per spec — do not regress these)
--------------------------------------------------------
- /api/contact/<secret> URL format (contract-level)
- CONTACT_API_SECRET — one shared secret per deployment; CORS is what tenancies
  the request. DonorNode uses the SAME secret value as the other tenants.
- Log event names: request_outcome, contact_secret_mismatch,
  recaptcha_transport_failure, ses_delivery_failure, unhandled_application_error
  (monitoring depends on them).
- SES template JSON files (ses-templates/*-v2.json) — verified they contain NO
  hardcoded wwt.co/webwiretech; they render via {{brand_*}} variables, so
  DonorNode branding works with zero template edits. Do NOT rewrite them.
- Sequential SES dispatch (admin first, confirmation second, halt on admin fail).


REMAINING TODO (handoff action item)
------------------------------------
Set CONTACT_TO_EMAIL_DONORNODE in Cloud Run (value provided separately; NO real
address was committed in the PR). Until it is set, DonorNode admin notifications
fall back to the global CONTACT_TO_EMAIL (info@wwt.co).

How to set it (Console or CLI). It persists across deploys because the deploy
action uses update-env-vars semantics (unlisted env vars are preserved):
  gcloud run services update contact-form \
    --region us-central1 --project donor-node \
    --update-env-vars CONTACT_TO_EMAIL_DONORNODE=<donornode-inbox@example>

Optional, only if per-tenant inbox split is later desired for the other tenants:
  CONTACT_TO_EMAIL_CLOUDVANTAGE, CONTACT_TO_EMAIL_WWT

Note: the deploy workflow (.github/workflows/deploy.yml) was intentionally NOT
modified — item 4d only required README/INIT.md/.env.local.example. The env var
is meant to be set directly in Cloud Run, not via GitHub vars/deploy.yml.
